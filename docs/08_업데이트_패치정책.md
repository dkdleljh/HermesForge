# 업데이트/패치 정책

## 버전 규칙
- Semantic Versioning 사용
- MVP는 `0.x`
- breaking change는 minor에서 명시적 공지

## 호환성 정책
- API 필드 제거는 deprecation 기간 후 진행
- 플러그인 인터페이스 변경 시 어댑터 제공

## 마이그레이션 원칙
- DB 변경은 단계별 migration 문서 제공
- 기존 snapshot 재해석 영향도 반드시 기록

## 플러그인 API 안정성
- `DomainPlugin` 필수 메서드 최소화
- 확장은 optional capability 방식 우선

## changelog 관리
- 기능/수정/보안 항목 분리 기록
- 릴리즈마다 테스트 결과 요약 첨부
