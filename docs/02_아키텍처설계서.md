# 아키텍처 설계서

## 전체 구조도
- Interface Layer: FastAPI Router, React UI
- Application Layer: Evidence/Patch/Snapshot/Materialize 서비스
- Domain Layer: Evidence/LambdaPatch/Snapshot/Context/RenderedEvent
- Infrastructure Layer: SQLite Repository, Plugin Registry, Safety Kernel

## 레이어 설명
- API는 서비스만 호출하고 비즈니스 규칙을 갖지 않는다.
- 서비스는 엔진/정책/저장소를 조합한다.
- 엔진은 생성/압축/병합/렌더 알고리즘을 담당한다.
- 저장소는 Repository 인터페이스 뒤로 숨겨 DB 교체를 단순화한다.

## 핵심 모델
- Evidence: 단서 입력
- LambdaPatch: 조건 기반 가능성 규칙
- Snapshot: patch 집합의 버전 단위
- Context: 렌더 조건
- RenderedEvent: 최종 안전 출력

## 데이터 흐름
1. Evidence 수집
2. GenerateCounterfactuals + Compress
3. Snapshot 생성
4. Materialize(snapshot + context)
5. SafetyKernel 정책 검사
6. RenderedEvent 반환/저장

## 플러그인 구조
- `DomainPlugin` 인터페이스 구현
- `PluginRegistry` 등록
- 코어 변경 없이 도메인 확장 가능

## 업데이트/패치 용이성
- SemVer 및 CHANGELOG 운영
- 설정 외부화(.env, data/seed)
- 정책 엔진 분리
- 저장소 인터페이스 기반 DB 전환
